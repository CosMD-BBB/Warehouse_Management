# Order Hub scope and invariants

Preserve the seven user-confirmed sources: Facebook, Shopee, TikTok Shop, Lazada, LINE OA, Review and Offline sales. Review means free products sent to reviewers/influencers, not affiliate revenue.

All sources within the same tenant consume one inventory pool. Marketplace quantities are mirrors, never summed into central stock. Server-side transactions reserve atomically; dispatch decreases physical and reserved quantities together; cancellation releases once. Review has zero sales and sold units; recognize its marketing product cost separately at dispatch, without double deduction. Production connectors still need ledger, outbox, SKU versions, retries, reconciliation and safety-stock rules.

Preserve multi-tenant isolation: derive tenant identity only from the authenticated session. Client tenant IDs cannot select another store. Scope users, state, connection drafts, audit and idempotency to the tenant. Usernames are unique per tenant; maintain one active admin per tenant. New stores have zero stock and no orders or financial history. Clear browser state when session/user/store changes and reject stale responses. Back up the actual user SQLite database before migration; never export it in a Cloud source bundle.

Manual orders require recipient/contact and a complete shipping address. Support multiple product lines with quantity, unit price, line/order discounts and shipping fees using cent precision. Cost comes from server product data. Aggregate SKU demand when reserving or dispatching, and apply the whole order atomically. Editing a reserved order before packing must preserve the previous order/reservations on shortage. Warehouse receives addresses and quantities but no prices, totals or payment fields. Payment verification is explicitly manual; do not imply bank/OCR verification.

This is a Node 24+ loopback app with SQLite persistence, actual login and server-enforced admin/warehouse/finance roles. Do not regress to browser-only security or a static app. Keep seed data, database and secrets outside the public directory. Warehouse responses must contain no financial fields. Revalidate sessions after asynchronous operations before mutations. Revoke sessions after role/active/password changes, preserve at least one active admin, and keep create/receive actions idempotent.

No actual platform/carrier connection exists. Retain clear sample labels for orders, stock publication and shipping. Connection onboarding saves only shop-name/link drafts and explains provider approval; never collect secrets into browser code or claim OAuth success without a verified callback and store identity. No real customer data in sample datasets.

Preserve user-supplied brand-logo.jpeg as the full login illustration, and use brand-icon.png (head only, red background) for website logos/favicons. Preserve red/cream CI and real platform logo assets, and bundled Manrope + Sukhumvit Thai. Show complete ranges in charts.
