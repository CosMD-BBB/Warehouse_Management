## เริ่มใช้งาน

1. ในโฟลเดอร์โปรเจกต์ รัน `npm start` แล้วเปิด Terminal ค้างไว้ (ชุดบน Mac เดิมมี `Start Order Hub.command` ให้ดับเบิลคลิกได้ แต่ตัวช่วยนี้ไม่ได้รวมใน repository)
2. เปิด http://127.0.0.1:4180/ แล้วระบุชื่อร้าน รหัสร้าน และสร้างบัญชี Admin ครั้งแรกด้วยชื่อผู้ใช้และรหัสผ่านของคุณเอง
3. เข้าเมนู **ผู้ใช้และสิทธิ์** เพื่อเพิ่มสมาชิก Warehouse และ Finance

ไม่มีรหัสผ่านเริ่มต้น บัญชีและการเปลี่ยนแปลงจะอยู่ต่อหลังรีเฟรชหรือปิดเปิดระบบใหม่ ไฟล์ `Order_Hub_Prototype.html` เป็นหน้าทางเข้าเท่านั้น ระบบต้องทำงานผ่านเซิร์ฟเวอร์เพื่อบังคับสิทธิ์และบันทึกข้อมูล ห้ามใช้ static file server แทน

ใช้ Node.js 24 สำหรับ repository นี้ รัน `npm ci --ignore-scripts` ก่อนตรวจชุดทดสอบหรือ build ส่วน `npm start` ยังคงใช้ SQLite ในเครื่องและไม่ต้องเชื่อม PostgreSQL ค่าเริ่มต้นของเซิร์ฟเวอร์รับเฉพาะ loopback การเปิดบน Node hosting ใช้ดิสก์ถาวรตาม `HOSTING.md`; Vercel ใช้ adapter และ PostgreSQL ตาม `VERCEL_SETUP.md`

## สิทธิ์

| บทบาท | การใช้งาน |
| --- | --- |
| Admin | ทุกหน้าจอ สร้าง/ยกเลิกออเดอร์ ตั้งค่าช่องทาง และจัดการผู้ใช้ |
| Warehouse | ข้อมูลออเดอร์เพื่อจัดส่ง กันสินค้า หยิบแพ็ก ส่งมอบ และรับสต๊อก ไม่มีราคา/ต้นทุน/ข้อมูลการเงินในข้อมูลที่เซิร์ฟเวอร์ส่งให้ |
| Finance | ดูและส่งออกรายงาน ยอดขาย ต้นทุน การเงิน และรายละเอียดออเดอร์ ไม่มีสิทธิ์แก้ไขสต๊อก/งานจัดส่ง |

การเปลี่ยนสิทธิ์ ปิดบัญชี และเปลี่ยนรหัสผ่านยกเลิกเซสชันเดิม ต้องเหลือ Admin ที่ใช้งานได้อย่างน้อยหนึ่งคน

## ร้านค้าและข้อมูลแยกกัน

เข้าใช้ด้วยรหัสร้าน ชื่อผู้ใช้ และรหัสผ่าน ทุกบัญชีผูกกับร้านเดียว เซิร์ฟเวอร์เลือกข้อมูลจากร้านของเซสชัน สมาชิก คำสั่งซื้อ สต๊อก รายงาน และแบบร่างเชื่อมต่อของแต่ละร้านแยกกัน ชื่อผู้ใช้ซ้ำข้ามร้านได้ หากอีกแท็บเปลี่ยนบัญชี ระบบล้างข้อมูลที่ค้างและให้เข้าใช้ร้านใหม่ก่อน

Admin เข้าเมนู **ร้านค้า** เพื่อเปลี่ยนชื่อร้าน คัดลอกลิงก์เข้าใช้ หรือสร้างร้านและเจ้าของร้านใหม่ ร้านใหม่มีรายการสินค้าเริ่มต้นที่สต๊อกศูนย์และไม่มีออเดอร์ การสร้างร้านไม่ให้ Admin เดิมเข้าใช้ข้อมูลร้านใหม่โดยอัตโนมัติ สต๊อกกลางรวมทุกช่องทางภายในร้านเดียวกัน

การเปิดฐานข้อมูลรุ่นเดิมด้วยเซิร์ฟเวอร์รุ่นนี้จะย้ายข้อมูลและบัญชีเดิมเข้าร้านเดียวโดยรักษารหัสผ่านและข้อมูลธุรกิจ แต่ยกเลิกเซสชันเก่า ต้องสำรองฐานข้อมูลด้วย SQLite backup API ก่อนอัปเกรด ขณะจัดทำไฟล์ส่งต่อ Cloud ยังไม่ได้อัปเกรดฐานข้อมูลจริงของผู้ใช้หรือยืนยัน browser QA รอบสุดท้าย ดู `CLOUD_HANDOFF.md`

## สิ่งที่ทดลองได้

- รับออเดอร์ตัวอย่าง เปิดออเดอร์ด้วยตนเอง ค้นหา กรอง รายละเอียด และส่งออก CSV
- ฟอร์มออเดอร์มีผู้รับ เบอร์โทร ที่อยู่จัดส่งครบและที่อยู่ออกบิลแยกได้ เลือกสินค้าได้หลายรายการ ค้นชื่อ/SKU เพิ่มลบ จำนวน ราคา ส่วนลด ค่าจัดส่ง ยอดรวม วันที่สร้าง ขนส่ง หมายเหตุ และแท็ก
- บันทึกวิธีโอนเงิน/COD และผลรับเงินที่ตรวจเอง ยังไม่มีอัปโหลดสลิป OCR หรือเชื่อมธนาคาร Review ฟรีทุกรายการและกันสต๊อกกลางของร้าน
- แก้ไขออเดอร์ก่อนเริ่มแพ็กได้ ตรวจและปรับการจองสินค้าทุกรายการในธุรกรรมเดียว หากสินค้าไม่พอระหว่างแก้ไขจะรักษาออเดอร์และการจองเดิมทั้งหมด
- กันสต๊อกกลาง ตรวจ SKU และจำนวนก่อนปิดกล่อง ส่งมอบขนส่งจำลอง และยกเลิกก่อนส่ง
- ใช้สต๊อกชุดเดียวทุกช่องทาง Marketplace แสดงยอดสะท้อนจากคลังกลาง ไม่ใช่ยอดที่นำมาบวกกัน
- Review มียอดขายเป็นศูนย์ กันและตัดสต๊อกตามจริงในชุดทดลอง แสดงต้นทุนสินค้าส่งรีวิวแยกจากต้นทุนสินค้าขาย
- ทดสอบการส่งยอดสต๊อกจำลอง ขัดข้อง และส่งยอดล่าสุดใหม่ รวมถึงเหตุการณ์ออเดอร์ซ้ำ
- รายงานยอดขาย สินค้า จังหวัด เงินรับ ค่าใช้จ่าย กำไรประมาณการ งานจัดส่ง และคุณภาพข้อมูล
- ตัวกรองวันที่ครบ 8 แบบ ใช้วันตามเวลาไทย: วันนี้, เมื่อวาน, 7 วันล่าสุด, 30 วันล่าสุด, เดือนล่าสุด, 3 เดือนล่าสุด, ปีนี้, ปีที่แล้ว
- 7/30 วันรวมวันนี้; เดือนล่าสุดคือวันที่ 1 ของเดือนนี้ถึงวันนี้; 3 เดือนล่าสุดคือเดือนนี้และสองเดือนก่อนหน้าถึงวันนี้; ปีที่แล้วคือ 1 มกราคมถึง 31 ธันวาคมของปีก่อน
- กราฟรวมรายเดือนเมื่อช่วงเกิน 90 วัน เพื่อแสดงช่วงปีครบถ้วน
- ตัวช่วยเชื่อมต่อช่องทางทีละขั้น บันทึกชื่อร้าน/ลิงก์ร้าน พร้อมคู่มือขอเชื่อม API แยก 7 ช่องทาง ระบุเจ้าของร้าน/ผู้พัฒนาต้องทำอะไร แนบลิงก์ทางการในแต่ละขั้น และเข้าคู่มือได้จากหน้าตรวจความพร้อม
- CI แดง/ครีม ไอคอนใบหน้าคุณลุงบนพื้นแดง และภาพเต็มที่ผู้ใช้ส่งสำหรับหน้า Login พร้อมโลโก้จริงของแพลตฟอร์ม ฟอนต์ Manrope และ Sukhumvit Thai อยู่ในโปรเจกต์

## ขอบเขตที่ยังไม่เชื่อมจริง

ข้อมูลออเดอร์ทั้งหมดเป็นข้อมูลสมมติ การซิงค์ร้าน สต๊อก marketplace ใบจ่าหน้า เลขติดตาม และขนส่งเป็นการจำลอง ไม่มีการส่งคำสั่งไปยังบัญชีร้านจริง ตัวช่วย API บันทึกเพียงแบบร่างการตั้งค่า ไม่รับ API secret และไม่อ้างว่าเชื่อมสำเร็จ การเชื่อมจริงยังต้องมีบัญชีนักพัฒนา แอป/สิทธิ์ที่แพลตฟอร์มอนุมัติ และการทดสอบกับร้านจริง

ต้นแบบเป็นหนึ่งคลังและหนึ่งพัสดุต่อออเดอร์ ยังไม่มีคืนสินค้าบางส่วน แยกพัสดุ กระทบยอดธนาคารจริง หรือ ledger สินค้าระดับ production การคืนเงินไม่เพิ่มสินค้ากลับคลังเอง ค่าใช้จ่ายตัวอย่างไม่ใช่อัตราบริการของแพลตฟอร์ม และรายงานกำไรไม่ใช่กำไรสุทธิทางบัญชี

## โครงสร้างและการบันทึก

- `server/index.mjs`: HTTP API, SQLite, scrypt password hashing, hashed session tokens, CSRF, role checks, audit และ idempotency
- `server/model.mjs`: การเปลี่ยนสถานะและการจอง/ตัดสต๊อกในธุรกรรมเดียว พร้อมตัดข้อมูลการเงินออกสำหรับ Warehouse
- `server/storage.mjs`: schema และการย้ายฐานข้อมูลรุ่นเดิม พร้อมข้อมูลแยกตามร้าน
- `server/seed.json`: ข้อมูลธุรกิจสมมติ ไม่เปิดเป็นไฟล์สาธารณะ
- `dist/`: หน้าจอและภาพประกอบ ไม่มี seed dataset อยู่ใน browser source
- `.local/order-hub.sqlite`: บัญชี เซสชัน ข้อมูลทดลอง และค่าตั้งช่องทาง เป็นข้อมูลส่วนตัวที่ห้าม commit หรือเผยแพร่ การสำรอง SQLite ต้องใช้ backup API หรือปิดระบบก่อนสำรองไฟล์พร้อม state ที่เกี่ยวข้อง

ระบบยังใช้ HTTP loopback สำหรับการทดลอง การนำขึ้นออนไลน์ต้องเปลี่ยนไป runtime ที่รองรับฐานข้อมูล/ธุรกรรม ใช้ HTTPS, secure cookies, สำรองข้อมูล, บันทึก ledger และเก็บ token แบบเข้ารหัส รวมถึง signed webhooks, outbox, rate limits, version checks, retries และ reconciliation ห้ามนำ `dist` ไปเผยแพร่เดี่ยว ๆ แล้วอ้างว่าระบบ Login ทำงาน
